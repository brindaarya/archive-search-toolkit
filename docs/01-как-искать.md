# Как искать в онлайн-архивах: правила, выведенные на практике

Эти правила появились не из теории, а из ошибок. У каждого указано, на чём обожглись.

## 1. Сначала зонд, потом пакет

Перед большим прогоном сделайте по одному запросу на каждый вариант формулировки и сравните число
находок. Так находится рабочая орфография (см. [02](02-дореволюционная-орфография.md)),
рабочий индекс и рабочая форма слова. Пакетный прогон по неудачной форме — потраченные часы
и ложный вывод «нет в архиве».

## 2. Не сужайте то, что не понимаете

* **Яндекс Архив: не задавайте `index`** (и помните, что с осени 2026 нужен вход в Яндекс ID, см. [05](05-яндекс-архив-через-браузер.md)).** Все ранние прогоны шли с `index=mass_media`, а это узкая
  периодика (за 1907 год — «Русский инвалид», епархиальные ведомости и одна томская газета).
  Без индекса в выдаче появляются **сканы ЦГА Москвы с OCR** (метрические, исповедные, ревизские)
  и «Русский архив». Ошибка найдена 18 сентября 2026 и обесценила часть прежних «ничего нет».
  В пакете `index` по умолчанию пустой.
* Движок объединяет слова по **И**; кавычки на фразу почти не помогают; сузить выдачу до одного
  издания или фонда нельзя. Редкие слова работают, «Быково + ферма» тонет в колхозных фермах.

## 3. Привязку проверяйте по окну, а не по документу

Первая версия скрипта привязывала находку к теме по тексту **всей** страницы и дала четыре ложных
«да»: слово «усадьба» и фамилия «Быков» стояли в разных фондах длинной аннотации, а условие
формально выполнялось. Правило: **считать привязку по окну ±300 знаков вокруг вхождения термина**,
не по документу целиком.

Отсюда же — работа с однофамильцами и омонимами:

* `Быковск*` — это прежде всего фамилия (архитектор Быковский), а не место. Прилагательное
  засчитывается только перед административным словом: `Быковск\w*\s+(волост|учил|земск|приход|станц)`.
* В «Яндекс Архиве» запрос по редкой фамилии даёт метрические книги с однофамильцами-крестьянами.
* Одно название села встречается в нескольких уездах и губерниях. Привязку к уезду проверяйте по
  заголовку выпуска или дела.

## 4. «Пусто» — не «нет». Отброшенный маркер проверяйте отдельно

Ильиных в ГПИБ «не было» — пока из сильных маркеров не убрали фамилию ради точности. Связка
`+Ильин* +Бронницк*` внутри серии «Вся Москва» дала готовую хронологию земской службы. Ищут не по
усадьбе, а по **уезду**: усадьба в адрес-календарях не упоминается вообще.
**Маркер, отброшенный ради точности, надо проверять прицельным запросом, а не считать тему пустой.**

## 5. Ищите на том уровне, на котором объект назван

| Тип дела | Как называется в описи | Как искать |
|---|---|---|
| Метрические книги | подшивка **по всей губернии**, в заголовке десятки приходов с номерами | по названию села, затем найти **номер позиции** прихода и листать до него |
| Ревизские сказки, исповедные ведомости | **по уезду**, село в заголовок не попадает | по названию уезда |
| Документы 1781–1796 | «округа», не «уезд» | оба слова |
| Адрес-календари | усадьбы нет вообще | по владельцам, должностям, уезду |

## 6. Номер скана не равен печатной странице

В ссылке ГПИБ `page/N` — номер **скана**. Обложка и титул сдвигают нумерацию: поиск показал страницы
18–19, а нужное было на печатных 14–15. Формула `id страницы = первый id + номер скана − 1` верна,
но привязку подтверждайте по **колонтитулу** в самом распознанном тексте.

## 7. Не выдавайте выборку за полный список

Радиусный запрос PastVu с лимитом 30 вернул 30 снимков из 202 — около 15%. Рабочий способ —
**сетка точек с перекрытием и склейка по идентификатору** (4×4 точки, шаг ≈0,0037° × 0,006°,
радиус 700 м, пауза 0,4 с). Графика (рисунки, чертежи, акварели) для радиусного поиска **невидима
вообще**: её берёт `photo.getByBounds` с `isPainting=1` либо `photo.givePS` по региону.
Правило: пока не знаете, сколько всего, пишите «найдено N, это выборка».

## 8. Если поиск на сайте «не работает» — это ещё не «данных нет»

* У prlib.ru форма поиска ломается (выдаёт весь фонд на любой запрос), зато работает подсказочный
  эндпоинт `prlib_sug` — до 5 результатов на категорию, берут множеством узких запросов.
* У Электронекрасовки фронтенд и API на разных хостах: `electro.nekrasovka.ru/api` отдаёт оболочку,
  а рабочий бэкенд — `api.electro.nekrasovka.ru/api`. Адрес API ищут в JS-файле страницы по
  слову `API_URL`. Поиск там всё равно не работает (проверено 5 ноября 2026).
* У КиберЛенинки в августе поиск казался сломанным (`found: 0`), а в ноябре с телом
  `{"mode":"articles","q":"…","size":20,"from":0}` заработал. **Прежде чем записывать «сайт сломан», повторите запрос
  в точности так, как его шлёт сам сайт** (вкладка Network).
* Сайты на Next.js/Nuxt (Яндекс Архив, ЦГАМО) отдают данные прямо в HTML, в
  `<script id="__NEXT_DATA__">` или `window.__NUXT__`. Браузер не нужен.
* Метод: открыть вкладку Network в инструментах разработчика, повторить поиск на сайте и посмотреть,
  какой запрос уходит.

## 9. Будьте вежливы с сервисами

* Пауза между запросами 0,4–2,5 с; для ЦГА Москвы и ГПИБ — не менее 0,8–1,5 с.
* `429 Too Many Requests` (ГПИБ) и «200 с нулём байт» (ЦГА Москвы) означают «притормозите».
  Лечится паузой и повтором; скрипты это умеют.
* **Капчу не обходить.** Остановиться, записать блокировку, дать человеку ссылку для ручной проверки.
* Условия Яндекс Архива запрещают массовое копирование сканов: берите тексты и отдельные листы, а не
  выгрузки.
* Для дорогих мест повторные запросы отдавайте из кэша; результаты складывайте в `results/`.

## 10. Относитесь к OCR как к наводке

Распознанный текст — подсказка, где открыть скан. Читают по образу страницы. Особенно в газетах:
блоки идут в порядке колонок, поэтому соседние абзацы перемешаны.

## 11. Что и как записывать

* **Шифр до листа:** фонд / опись / дело / лист и ссылка на скан. Без шифра находку невозможно
  перепроверить.
* **Журнал поиска:** запрос, источник, дата, результат (нашлось / не нашлось / блокировка).
  Нулевые результаты записываются.
* **Привязка:** `да` / `вероятно` / `нет данных`, с указанием по какому окну текста.
* **Не склеивайте** разные учреждения и разные сёла с одним названием. «В Быкове» не равно «в усадьбе».
* Для родственных связей действует строже: см. навык в `skill-ex-ussr-kinship-research` — две
  независимые цепочки доказательств, копии одного источника не считаются двумя.

## 12. Работа с файлами

* **PDF.** Заранее проверьте текстовый слой: в сыром файле посчитайте `/Font` и `/ToUnicode`.
  Если `/ObjStm > 0`, по сырым байтам судить нельзя. `Get-PdfText.ps1` читает потоки `Tj/TJ`, умеет
  перекодировать latin-1 → cp1251 и показывает дореформенный текст со сканов РГБ. Современные
  делопроизводственные PDF со шрифтовыми подмножествами требуют разбора таблицы `/ToUnicode`.
* **DjVu** ничем из этого набора не читается — его можно только отдать человеку.
* **НЭБ** отдаёт PDF напрямую:
  `https://rusneb.ru/local/tools/exalead/getFiles.php?book_id=<ID>&name=<ID>&doc_type=pdf`,
  где ID вида `000199_000009_006709065` берётся из адреса карточки `/catalog/<ID>/`.

## 13. Когда онлайн закончился

Не повторяйте поиски по кругу. Скажите это один раз, подготовьте письменные запросы в архивы и
вопросы родственникам. Помните про практические ограничения: например, в читальном зале отдела
рукописей РГБ нужен читательский билет **и письмо-отношение организации** (ежегодно обновляется), а
**самостоятельное фотографирование рукописей запрещено** (по информации сайта на 22 августа 2026;
уточняйте перед визитом).
